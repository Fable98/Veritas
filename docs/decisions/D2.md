# ADR D2: Reservation Accounting, Challenger Bond Parameterization, and Rollover Rules

- **Status**: Proposed
- **Date**: 2026-11-03
- **Invariants Touched**: INV-1, INV-3, INV-5, INV-6, INV-7, INV-8

## Context

When an escrow is opened, funds must be reserved to guarantee payment upon delivery. Furthermore, if a seller delivers fraudulent or non-compliant work, the buyer must post a challenger bond to initiate dispute resolution.

If the challenger bond is only reserved on-demand when a challenge occurs, a malicious seller or parallel agent process could exhaust the buyer mandate's remaining budget before the challenge is submitted. In that case, `reserve` would revert, preventing the challenge and destroying dispute liveness (breaking INV-5 and INV-6).

## Decision

1. **Pre-reserving Challenger Bond**:
   - Escrow creation atomically reserves `price + challengerBondAllowance` in the mandate ledger.
   - `challengerBondAllowance = maxChallengerBondBps * price / 10_000` (the *allowance*). The actual challenger bond posted at challenge time may be smaller than the allowance.
   - Reserving the bond upfront guarantees that dispute liveness is preserved regardless of subsequent transactions.

2. **Parameterization via Mandate (`maxChallengerBondBps`)**:
   - The bond allowance is an explicit parameter on the mandate: `maxChallengerBondBps` (basis points of escrow price).
   - Governed by INV-3:
     - Raising `maxChallengerBondBps` is a loosening and requires a matured timelock.
     - Lowering `maxChallengerBondBps` is a tightening and takes effect immediately, subject to the lower bound `committed + reserved + delegated` (see rule below).

3. **Immediate Tightening Invariant Protection Rule**:
   - Immediate tightening could break INV-1 if a mandate owner or guardian lowers `budget` below current commitments.
   - *Rule*: Reject any parameter tightening that would result in `budget < committed + reserved + delegated`. This applies to all tightenable parameters; the lower bound is `committed + reserved + delegated`, consistent with INV-1 as stated per window (which includes `delegated`).
   - Rejecting invalid tightenings maintains INV-1 as an inviolable invariant across all state transitions and simplifies formal verification proofs.

4. **Early Challenger Bond Release**:
   - If the challenge window elapses without dispute (`unchallenged`), the unused challenger bond portion is immediately released back to available budget (`reserved -= challengerBond`).
   - *Trigger Mechanism*: Released via a permissionless `releaseBond(bytes32 escrowId)` entrypoint on `EscrowSettlement` (callable by any keeper/bot), or lazily executed on the next ledger interaction / final settlement.
   - *Safety on Frozen*: Releasing the bond must **never revert on `Frozen` status**, ensuring budget recovery cannot be trapped if a mandate is defensive-locked.

5. **State Transition Accounting Table & Value Conservation (INV-7)**:
   - For every escrow state transition, ledger changes are defined as follows.
   - `bond` in the table denotes the *allowance* (`maxChallengerBondBps * price / 10_000`); `actualBond` denotes the bond actually posted by the challenger (≤ `bond`).
   - The difference `bond − actualBond` (the *unneeded allowance*) must never remain reserved indefinitely: it is released to `available` at challenge time (if a challenge occurs before early release), or at terminal state if the early-release path fires before any challenge.

| Outcome | $\Delta \text{reserved}$ | $\Delta \text{committed}$ | $\Delta \text{available}$ | Notes |
|---|---|---|---|---|
| **Open Escrow** | $+(\text{price} + \text{bond})$ | $0$ | $-(\text{price} + \text{bond})$ | Atomic reservation upon escrow creation; `bond` = allowance |
| **Challenge Elapsed** (Unchallenged) | $-\text{bond}$ | $0$ | $+\text{bond}$ | Early bond release before terminal settlement; full allowance returned because no challenge was raised |
| **Challenge Raised** | $-(\text{bond} - \text{actualBond})$ | $0$ | $+(\text{bond} - \text{actualBond})$ | Unneeded allowance released immediately at challenge time; `actualBond` stays reserved while funds sit in `BondManager` |
| **Settled** (100% to seller, unchallenged) | $-\text{price}$ (and $-\text{bond}$ if not released) | $+\text{price}$ | $0$ (or $+\text{bond}$ if not released) | Price moves from reserved to committed |
| **Refunded** (100% to buyer) | $-\text{price}$ (and $-\text{bond}$ if not released) | $0$ | $+\text{price}$ (and $+\text{bond}$ if not released) | Price and bond return to buyer available |
| **Split** ($S$ to seller, $B$ to buyer, $S+B = \text{price}$) | $-\text{price}$ (and $-\text{bond}$ if not released) | $+S$ | $+B$ (and $+\text{bond}$ if not released) | Commits only seller's share $S$; buyer share $B$ released |
| **Resolved, buyer wins** | $-(\text{price} + \text{actualBond})$ | $0$ | $+(\text{price} + \text{actualBond})$ | Price and actual bond restored to available. Any seller slash received is protocol/external income, NOT restored budget. (Allowance surplus already released at challenge time.) |
| **Resolved, seller wins** | $-(\text{price} + \text{actualBond})$ | $+(\text{price} + \text{bond\_slashed})$ | $0$ | Price and slashed portion of *actual* bond move to committed (paid/slashed). `bond_slashed ≤ actualBond`. (Allowance surplus already released at challenge time.) |

   *Delta consistency check for seller-wins row*: `reserved` decreases by `price + actualBond`; `committed` increases by `price + bond_slashed`; the difference `actualBond − bond_slashed` goes to the challenger as a partial return and is handled by `BondManager`, not the mandate ledger. The mandate ledger itself is balanced because `BondManager` holds `actualBond` and distributes it externally.

6. **Rollover Dynamics & Safe Conservatism**:
   - Invariant INV-1 is evaluated strictly per window $w$, including `delegated`:
     $$\forall w: \text{committed}_w + \text{reserved}_w + \text{delegated}_w \le \text{budget}_w$$
   - At a window rollover boundary ($w \to w+1$):
     - `committed` resets to 0.
     - `reserved` and `delegated` carry over into window $w+1$.
   - *Capacity Neutrality in Later Windows*: An escrow opened in window $w$ occupies `reserved` capacity in window $w+1$ from the start of the window. When that escrow finalizes in window $w+1$, `reserved` drops by `price` and `committed` increases by `price`, resulting in $\Delta(\text{committed}_{w+1} + \text{reserved}_{w+1}) = 0$. The conversion is capacity-neutral for window $w+1$.
   - *Safe Conservatism*: A long-running escrow occupies reservation capacity in both window $w$ and window $w+1$. This conservatism is documented as intentional to guarantee that committed liabilities are always backed by budget.

## Consequences

- **Positive**:
  - INV-5 and INV-6 dispute liveness is guaranteed; buyer agents cannot be griefed out of challenging by parallel budget exhaustion.
  - Value conservation (INV-7) is fully anchored across both unchallenged and challenged dispute paths.
  - Unused bonds do not remain locked unnecessarily until final escrow settlement.
  - The unneeded allowance (`bond − actualBond`) is returned promptly at challenge time, ensuring no path leaves the difference reserved forever.
- **Negative**:
  - Escrows spanning window boundaries consume capacity in both windows.
- **Rejected Alternatives**:
  - *On-demand bond reservation*: Rejected because it allows attackers to front-run challenges by consuming remaining budget, breaking dispute safety.
